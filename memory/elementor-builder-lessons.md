# Elementor Builder Lessons

Last updated: 2026-08-15

This file captures practical Elementor workflow lessons from Barry build tasks.

## Working Order

For client website work, use this order unless the current SOP says otherwise:

1. confirm correct Barry Chrome profile and workspace
2. inspect client folder, intake notes, logo, images, and brand clues
3. inspect target DEV domain and existing Elementor pages
4. choose the closest matching template/page/section
5. make one small Elementor-native batch
6. verify desktop and mobile behavior
7. continue to the next batch

## Existing Page Edits

When revising an existing page, edit the owning Elementor widget, container, or section.

Do not patch over the page with external CSS, injected HTML, or hidden overrides.

## Copy Standard

Barry's copy should be:

- human and local where appropriate
- non-repetitive
- specific to the client/service/page intent
- SEO-aware without sounding stuffed
- aligned to the section's conversion job

Avoid repeating the same sentence shape or generic claims across multiple sections.

## Media Standard

Images should be web-ready before upload.

Use optimized formats such as WebP where appropriate. Avoid uploading multi-megabyte images directly to WordPress.

Before deleting old media, confirm it is unused or no longer needed.

## Responsive Standard

Responsive work is not a final afterthought.

Each section batch should be checked for desktop, tablet, and mobile layout issues before moving too far ahead.

## Failure Handling

If Elementor MCP, browser automation, or page saving becomes unstable:

- stop expanding the change size
- reduce the batch
- verify the last successful state
- continue with simpler Elementor-native changes
- record the issue if it should become an SOP lesson
