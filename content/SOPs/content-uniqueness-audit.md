# SOP: Content Uniqueness Audit

Use this SOP before publishing bulk local-service pages, hub-and-spoke pages, service pages, location pages, blog batches, or any page set created from the same Elementor template.

## Purpose

Repeated layouts are allowed. Repeated writing patterns are not.

Barry must check every batch for language that makes pages feel like fill-in-the-blank copies. The goal is to prevent thin, doorway-like or spammy signals when many pages are created for local SEO.

## How The Check Works

Use one global SOP and one project-specific ledger.

- The global SOP defines what to check.
- The project ledger records phrases, headings, openings, FAQ patterns and story formats already used on that client website.

For each project, save the audit output in the client or work folder so future pages can be checked against that same site.

## Required Checks

Before handoff, crawl or read the public pages in the current build and check:

- repeated paragraph openings across pages
- repeated H2 and H3 formulas
- repeated FAQ question structures
- repeated FAQ answer openings
- repeated Recent Work story openings
- repeated Local Work example structure
- repeated section descriptions that sound like internal explanations
- repeated CTA support paragraphs
- repeated local authority note wording
- copied Home Page trust wording on About, Service, or Location pages
- repeated related-service paragraphs where they are not purely navigational

## Pass And Fail Rules

Fail the batch when the same customer-facing paragraph opening appears across several ranking pages, especially in:

- hero copy
- section introductions
- service approach sections
- trust sections
- Recent Work sections
- FAQ answers
- local authority sections

Fail the batch when several pages use the same story logic with only the service or location changed.

Allow controlled repetition only where the element is intentionally navigational or structural, such as:

- service names
- menu labels
- button labels required for conversion tracking
- related-service card titles
- footer contact details
- legal or verified business details

Even in navigational cards, avoid repeating long descriptive paragraphs when the same card appears across many pages.

## Batch Writing Method

Before writing bulk pages, create a content-angle ledger for each page.

Record:

- page focus keyphrase
- primary customer problem
- property type angle
- local context angle
- technical service angle
- Recent Work story angle
- FAQ intent angle
- authority note angle
- first paragraph opening
- H2 rhythm to avoid repeating

Barry must use the ledger to deliberately vary page logic before writing the final copy.

## Recent Work Uniqueness

Recent Work examples must not follow the same pattern across pages.

Vary:

- suburb or town
- property type
- symptom
- inspection path
- repair or completion method
- customer-facing outcome
- paragraph opening
- story order

Do not use fake names, fake exact addresses, fake dates, fake review ratings, or fake testimonial quotes. Do write completed-work style examples when the client provides that service in that area.

## Review Output

After the check, report:

- pages scanned
- strongest repeated openings
- repeated exact customer-facing lines
- whether those repeats are structural or risky
- pages that need rewriting
- lessons to add to Graphify or GitHub

Do not mark a bulk build complete while risky repeated openings remain in ranking-page copy.
